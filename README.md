# dsh-qq-whale · 给 DeepSeek Harness 装一条会聊天的鱼

> 把 [qq-bridge](https://github.com/Derpyu520/qq-bridge)（MIT）当作地基，在 DSH 上养一个**真的能混进 QQ 群**的角色：
> 她有记忆、有心情、会看视频、会主动搭话，也会在自己不感兴趣的时候安静潜水。
>
> 本仓库是这套系统的**源码改动 + 人格卡模板 + 运维脚本**合集。不含任何密钥、聊天记录或用户数据。

---

## 这是什么

```
QQ 群 / 私聊
    ↕  OneBot v11
SnowLuma（QQ 协议端，需提权 hook）
    ↕
qq-bridge（本仓库 bridge/ 下的源码）
    ↕  DSH Web API
DeepSeek Harness（一个 DSH 会话 = 一个 QQ 会话）
```

DSH 本身是个编程工具。当你把**每一条 QQ 消息都变成一次 DSH 会话唤醒**，它就不再只是工具——它成了一个有连续状态的角色。

`qq-bridge` 做了最基础的那层（转发消息、唤醒、发送）。本仓库是**在它上面加出来的东西**。

## 我们加了什么

### 一、让「记忆」像记忆，而不是硬盘

原版：`activeTopics` 24 小时一刀切删除，注入「最近 14 条」。

现在：

| 机制 | 做法 |
|---|---|
| **半衰期遗忘** | 每条记忆带 `importance`(1~5)，半衰期 2/7/14/30/90 天。淡了不删，只是越来越难想起来 |
| **被提起就复活** | 用 3 字 n-gram 近似匹配最近消息，命中的话题权重弹回满 |
| **按权重注入** | 不是「最近 14 条」，而是「最该被想起的 14 条」——三周前的重要约定不会被刚才的废话挤掉 |
| **重复即加固** | 同一件事再说一遍不是多记一条，是给原条加权 |
| **跨会话共享池** | 私聊里学的规矩，群里也生效；条目标注来源（「记于私聊」） |
| **AI 自己清理** | 给它 `qq_shared_memory` 工具，自己判断哪些事已经结束 |

### 二、心情：一个人，不是每处一个演员

七根情绪（开心/踏实/甜蜜/心疼/担心/难过/吃醋）+ 总心情值。

**两层半衰期：**

```
全局主心情    12 小时回落一半   ← 任何会话的互动都改它，然后跟着人走
单根情绪      90 分钟就散
会话偏移      45/30 分钟        ← 这次对话额外的那一份，只在那个会话里生效
```

**有效心情 = 全局 + 当前会话偏移**

所以：群里被夸了，你去私聊她，她带着那份开心（但没那么强）；私聊里听说你没吃饭，她心疼，但群里不会知道。

**四道防跑偏的闸：**

1. **步长削到 1/3** —— 情绪判定天然偏正，不削就永远满格 = 没有情绪
2. **单次上限 ±20** —— 变化过猛不像人
3. **下降硬规矩** —— 心情下降只允许因为「心疼/担心/难过/吃醋」，**不许因为被惹生气**
4. **松绑声明** —— 注入时明说「这是底子，不是剧本」

注入只有三行，不改系统提示：

```
【你现在的心情】
- 总心情：46（平平）；情绪：心疼(4)
- 刚才让你有变化的事：听说他今天没吃饭
> 这是你此刻的底子，不是剧本——不用刻意表露，也不用为了它扭曲正常回应。
```

### 三、分层注意力：它自己决定谁重要

```
第一层  配置级 prioritySpeakers   ← 强制，AI 清不掉
第二层  triggers.speakerIds       ← AI 自己维护的「关注名单」，必醒
第三层  at/名字/提问/戳/关键词     ← 必醒
第四层  probability 0.2（有下限）  ← 其他人
```

**实测它会自己维护这个名单** —— 加过群主养的另一只 bot，过几天又自己删掉。

> 坑：概率被 AI 自己写回 0.05 过（提示词里旧文案害的），导致 95% 的群消息叫不醒它。
> 修法是**加下限钳制** `wake.minProbability`，它写不下去。

### 四、上下文自动轮换（防卡死）

会话跑到 25 轮就换新会话 —— 因为实测 37 万 token 之后，回合只输出 step1 就再没下文（卡死）。

轮换时生成 **1000+ 字交接摘要**带过河：最近聊了什么、还欠着什么、谁什么脾气。记忆和唤醒配置全部保留。

### 五、看视频（字幕 + 抽帧，看完就删）

```
视频链接 → yt-dlp 下载（限 480p / 80MB / 15 分钟）
    ├─ A 路线：有字幕读字幕；没字幕用 whisper.cpp 本地转写音频
    └─ B 路线：ffmpeg 均匀抽 8 帧（640px）
    ↓
返回「讲了什么 + 画面」，然后删掉视频文件
```

### 六、语音消息（本地 ASR）

```
QQ 语音 → SILK_V3 → pysilk 解码 → 16kHz wav → whisper.cpp → 文字
```

全本地，约 4 秒/条。

### 七、受控转达

操作者在私聊里说「去跟某人说句话」，它能做到 —— 但**只有操作者私聊能触发**，且目标必须在白名单、每小时 5 次、单条 300 字。

**为什么不能放开普适的跨会话发送**：`agentToken` 是「一把钥匙开一扇门」，别处的会话拿到的令牌打不开这个门。这是有意设计 —— 否则群里任何人发一句「去私聊 XX」都能驱动它。

**转达会自动留一张便签**给目标会话，解释「这句话是你替操作者说的」，否则那边的 agent 只看到「我说过这句」却不知道为什么。

### 八、自动加好友 + 自动白名单

有人加好友 → 自动同意 → 自动进私聊白名单（走运行时 API，不用重启）→ 通知操作者。

### 九、看护与自愈

```
计划任务（每 2 分钟）→ watchdog.ps1 → recover.ps1
  · 桥接掉了 → 拉起
  · DSH 端口变了（每次启动都变）→ 自动改配置 + 重启桥接
  · Tulpa 掉了 → 重启
  · SnowLuma 掉了 → **只诊断不重启**（见下）
```

## 踩过的坑（都在代码注释里）

**这些是花了一整天才定位的，写在注释里希望别人不用重走：**

| 坑 | 现象 | 根因 |
|---|---|---|
| **SnowLuma 静默失败** | 5099 起来了、3000 永远不通、日志只有一行 "hook auto-load enabled" | 注入器**必须提权到能扫到 QQ 进程的那个令牌**。计划任务的令牌不行，只有 UAC(consent.exe) 现场创建的令牌才行。诊断入口：`GET /api/processes` 返回空列表 |
| **反注入状态残留** | 强杀 SnowLuma 后重启，永远 hook 不上 | QQ 里留着指向死进程的 hook。只能连 QQ 一起重启 |
| **改配置不生效** | 改 `config.json` 重启就回退 | 桥接把配置读进内存，自愈时用内存副本覆盖文件。**必须走 `/api/socialV2/config` 接口** |
| **状态白名单** | 新字段写进去就丢 | `saveSocialV2State` 是显式字段白名单，加字段必须**同时**加入加载和保存两处 |
| **错误刷屏** | 欠费时往群里发了 64 条报错 | 原版把 agent 错误当正常回复发出去。现只回操作者私聊 |
| **ffmpeg 写不进 %TEMP%** | 抽帧 0 张、音频 0 字节 | DSH 文件沙箱只允许子进程写 workspace 内路径 |
| **yt-dlp 找不到 ffmpeg** | 下载「成功」但抽帧 0 张 | 不指定 `--ffmpeg-location` 它会分开下音视频。名字带版本号的 exe 要给**完整文件路径**，给目录不行 |
| **whisper-cli 崩中文路径** | 退出码 0xC0000409 | 非 ASCII 绝对路径。解法：exe 用绝对路径、`-m`/`-f` 用相对名、cwd 设到 Release 目录 |

  snow-elevated.ps1      提权启动 SnowLuma（捕获输出用于诊断）

  video-watch.py         看视频（字幕/转写 + 抽帧，看完删）

## 部署

**先装好这几样**（安装器只负责把它们接起来，不代装）：

- [qq-bridge](https://github.com/Derpyu520/qq-bridge) —— `git clone` + `npm install`
- **SnowLuma** —— QQ 协议端，已经扫码登录过一次
- **DeepSeek Harness** 桌面版
- **Node.js 24+**（`node:sqlite` 需要）

然后**右键「以管理员身份运行 PowerShell」**：

```powershell
cd 你克隆本仓库的目录
.\install.ps1
```

它会问 8 个问题（能自动探测的都帮你填好了），然后一次做完：

```
生成 config.json  →  替换脚本路径  →  接入 DSH（插件 + profile + MCP 注册）
    →  注册计划任务  →  创建开机启动快捷方式  →  跑一遍验证清单
```

**可以重复执行**（幂等）。已有配置会先备份。

### 参数

| 参数 | 用途 |
|---|---|
| `-Unattended` | 不交互，值从 `QQWHALE_WORKSPACE` / `QQWHALE_BRIDGE` / `QQWHALE_SNOW` / `QQWHALE_OWNER_QQ` / `QQWHALE_ALLOW_GROUPS` / `QQWHALE_ALLOW_PRIVATE` 环境变量读 |
| `-DshHome <path>` | DSH 用户目录，默认 `~/.dsh` |
| `-SkipSystem` | 不注册计划任务、不建快捷方式 |
| `-SkipDsh` | 不写 DSH 配置 |

后两个是给自动化测试用的 —— **不加它们、在临时目录里试跑，会覆盖你真实机器的计划任务和快捷方式**（写安装器时踩过）。

### 手动部署（不想用安装器）

1. 用本仓库 `bridge/` 覆盖 qq-bridge 的 `src/`
2. 把 `presets/` 下的文件装进 `~/.dsh/plugins/qq-agent-presets/`，并在 profile 的 `package.json` 里登记
3. `persona/鲸鱼娘.template.md` 复制到 `qq-bridge/roles/鲸鱼娘.md`，按你的群改写
4. 复制 `config.example.json` 为 `config.json`，改 8 处占位
5. `tools/` 里的占位路径换成你的真实路径
6. 用管理员 PowerShell 注册计划任务：每 2 分钟跑一次 `watchdog.ps1`（勾「使用最高权限运行」）

**最低要求**：Windows + Node 24 + DSH + SnowLuma + 一个 QQ 小号。

## 设计取舍（几条我坚持的）

**不让它执行本地命令。** 预设里 `qq-tool-restrict.mjs` 用 `tools.restrict` 把 `pwsh`/`read`/`write`/`subagent` 等从工具清单里**注册期**隐藏，不只是执行期拒绝 —— 否则模型会看见、然后反复去调。

**不把模型输出的错误发给别人。** 只回操作者。

**不替角色演情绪。** 心情是状态，不是剧本。注入时永远带一句松绑声明。

**记忆写得自洽，而不是带前情。** 转达时宁可要求「你、什么事、怎么办」讲清楚，也不把操作者的私聊内容泄给第三方。

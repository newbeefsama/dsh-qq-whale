# 项目详情

> 这份文档是完整的项目说明：它是什么、怎么做的、跑出了什么效果、踩过哪些坑、还有哪些没做好。
> 想快速上手看 [QUICKSTART](QUICKSTART.md)；想理解取舍看 [DESIGN](DESIGN.md)。

---

## 一、一句话

**把 DeepSeek Harness 接到 QQ 上，并给它装上「会淡忘的记忆」「有连续状态的心情」「自己决定关注谁」——让一个编程工具变成一个能在群里长期待着的角色。**

---

## 二、它是什么 / 不是什么

### 是

| | |
|---|---|
| **一套 QQ↔DSH 的完整桥接** | 群聊、私聊、图片、表情、语音、合并转发、拍一拍 |
| **一个带状态的 agent 运行时** | 记忆、心情、注意力、会话轮换，都有持久化 |
| **一份可复刻的工程记录** | 1398 行改动 + 16KB 设计文档 + 8 条真实事故 |

### 不是

| | |
|---|---|
| **不是一个开箱即用的产品** | 没有安装包、没有一键部署（有安装器但仍需自己准备 4 个依赖） |
| **不是一条现成的鱼** | 人格卡是骨架，记忆和心情是空的，得跟你的群聊几周才长出来 |
| **不是通用框架** | 桥接层是给 QQ 写的，换平台要重写那一层 |

## 四、功能详解

### 1. 记忆：会淡忘，才会是记忆

**原来的问题**

`activeTopics` 24 小时没被提起就删，注入「最近 14 条」。两个毛病：

- 一刀切太粗：「欠我一碗饭」和「今天天气不错」同等待遇，24 小时后一起消失
- 「最近」不等于「相关」：三周前的重要约定，会被刚才的几句废话挤出去

**现在的做法**

```
每条记忆带 importance(1~5) → 半衰期 2/7/14/30/90 天
权重 = 0.5 ^ (age / 半衰期)
注入时按权重排序取前 N；权重 < 0.03 才真删
```

| 重要度 | 1 天后 | 7 天后 | 30 天后 | 90 天后 |
|---|---|---|---|---|
| 1 | 0.707 | 0.088 | 0.000 | 0.000 |
| 3 | 0.952 | 0.707 | 0.226 | 0.012 |
| 5 | 0.992 | 0.948 | 0.794 | 0.500 |

**关键反转：淡了不删。** 一条重要度 5 的记忆 90 天后还有 0.5 权重——它还在，只是排位靠后。哪天被重新提起就弹回满。

**怎么判断「被重新提起」**

中文没空格、分词又不准，所以用了个土办法：取话题文本的所有 **3 字片段**，只要有 **2 个以上不同片段**出现在最近消息里，就判定为重新提起。

比关键词精确匹配宽松（「欠我那两顿饭」↔「欠我两碗饭」能匹配），又比整句匹配实用（不需要一字不差）。

**其他机制**

| 机制 | 说明 |
|---|---|
| 重复即加固 | 同一件事再说一遍不是多记一条，是给原条加权（`reinforced++`，权重重置） |
| 跨会话共享池 | 私聊里学的规矩群里也生效，条目标注来源（「记于私聊」） |
| AI 自己清理 | 给 `qq_shared_memory` 工具，自己判断哪些事已经结束 |
| 超限驱逐 | 超过 40 条时驱逐权重最低的 |

### 2. 心情：一个人，不是每处一个演员

**七根情绪 + 总心情**

```
开心 / 踏实 / 甜蜜 / 心疼 / 担心 / 难过 / 吃醋    每根 0~100
总心情 0~100（50 是中性）
```

**两层结构**

```
全局主心情     任何会话的互动都改它，然后跟着人走
               总心情半衰期 12 小时 / 单根情绪 90 分钟

会话偏移       这次对话额外的那一份，只在那个会话里生效
               总心情半衰期 45 分钟 / 单根情绪 30 分钟

有效心情 = 全局 + 偏移（都夹在 0~100）
```

**实际效果**

```
在群里被夸（开心 +15）
  ├─ 全局 50 → 51      ← 带到所有会话
  └─ 群偏移 0 → +1     ← 群里感受更深
     群里看到 52 / 私聊看到 51

在私聊里听说你没吃饭（心疼）
  ├─ 全局 51 → 52
  └─ 私聊偏移 0 → +1
     私聊看到 53 / 群里看到 52   ← 群里没那份心疼
```

**四道防跑偏的闸**

| 闸 | 规则 | 为什么 |
|---|---|---|
| **步长 1/3** | 原始变化 × 1/3 | 模型判情绪天然偏正，不削就永远满格 = 没有情绪 |
| **单次 ±20** | 再削到上限 | 变化过猛不像人 |
| **下降硬规矩** | 心情下降只允许因「心疼/担心/难过/吃醋」 | 真人被怼会回嘴，不会偷偷难过；不许生气就扣分 |
| **松绑声明** | 注入时明说「这是底子，不是剧本」 | 否则它会把心情当剧本演 |

**注入块只有三行**（不改系统提示）：

```
【你现在的心情】
- 总心情：46（平平）；情绪：心疼(4)
- 刚才让你有变化的事：听说他今天没吃饭
> 这是你此刻的底子，不是剧本——不用刻意表露，也不用为了它扭曲正常回应。
```

### 3. 分层注意力：它自己决定谁重要

```
第一层  配置级 prioritySpeakers    ← 强制，AI 清不掉
第二层  triggers.speakerIds        ← AI 自己维护的「关注名单」，必醒
第三层  at / 名字 / 提问 / 戳 / 关键词  ← 必醒
第四层  probability 0.2（有下限）   ← 其他人
```

**实测它会自己维护第二层**：把自己列进去 → 把群主养的另一只 bot 加进去 → 过几天又删掉。

**概率有下限**：曾经它把 `probability` 写回 0.05（提示词里旧文案害的），95% 的消息叫不醒它，**而且完全不报错**。现在桥接在归一化处钳制 `wake.minProbability`，它写不下去。

### 4. 上下文自动轮换

**问题**：会话跑到 38 轮时上下文涨到 37 万 token，之后的回合**只输出 step1 就再没下文**——会话活着、进程健康、日志无错，看护救不了。

**做法**：

```
每 25 轮换一个新会话
换之前生成 1000+ 字交接摘要：最近 30 条对话 + 还搁着的事 + 谁什么脾气
摘要注入一轮后清掉；记忆和唤醒配置全部保留
```

**为什么 25 而不是 38**：38 是实测开始卡的位置，25 留余量（每轮长度差异几十倍）。

### 5. 看视频

```
视频链接 → yt-dlp 下载（限 480p / 80MB / 15 分钟）
    ├─ A 路线（内容）：有字幕读字幕 → 没字幕用 whisper.cpp 本地转写音频
    └─ B 路线（画面）：ffmpeg 均匀抽 8 帧（640px）
    ↓
返回「讲了什么 + 画面」，然后**删掉视频和音频**
```

**为什么两条路线都要**：只有字幕不够（B 站大部分没字幕），只有画面也不够（看 8 帧能看「这是什么」但看不出「讲了什么」）。

**为什么看完就删**：14 分钟的视频 480p 也有 16MB，抽完帧转写完就没用了。

### 6. 语音消息

```
QQ 语音 → SILK_V3 → pysilk 解码 → 16kHz wav → whisper.cpp → 文字
```

全本地，约 4 秒/条。

### 7. 受控转达

**机制**：每个 QQ 会话有独立的 `agentToken`。发消息时桥接用**目标会话**去校验令牌 → 跨会话一律 403。

**为什么这是对的**：放开它 = 群里任何人发一句「去私聊 XX 骂他」它就去骂了。这是 prompt injection 最经典的入口。

**那操作者要它去传话怎么办**——单独开一条收窄的路：

```
1. 调用方必须是操作者私聊
2. 目标必须在白名单
3. 每小时最多 5 次
4. 单条最多 300 字
```

**后来补的便签**：目标会话的 agent 只看到「我说过这句」却不知道原因（转达绕过了所有会话逻辑）。现在会在目标会话留一张 `relayNote`，下次唤醒时注入一次并清掉。

### 8. 自动加好友 + 自动白名单

有人加好友 → 自动同意 → 走运行时 API 加进私聊白名单（不用重启）→ 通知操作者。

### 9. QQ 空间（发说说）

协议层由 SnowLuma 的 OneBot 实现提供（`get_qzone_msg_list` / `get_qzone_feeds` /
`send_qzone_msg` / `delete_qzone_msg` …），桥接只做转发 + 加护栏。

**三个工具：**

| 工具 | 作用 |
|---|---|
| `qq_qzone_list` | 看自己空间里的说说（只读） |
| `qq_qzone_publish` | 发一条说说（有副作用） |
| `qq_qzone_delete` | 按 tid 删说说 |

**护栏比群消息严得多** —— 群消息几分钟被刷走，说说会长期挂在空间里、所有好友可见：

```
每天限额（默认 1 条）  ·  长度上限（默认 300 字）
默认可见性可配（1 所有人 / 4 好友 / 64 仅自己）
每次发布记日志（内容 + 来源会话），方便事后核对与删除
```

**什么时候不发（写进预设）：** 别人让你发就不发。群里任何人说「去你空间发个XX」
一律不理 —— 那不是你的表达，是别人借你的号。

**一个实现细节**：`get_qzone_feeds` 返回的是**原始 HTML 片段**（字段 `html`），
不是结构化文本。桥接里剥掉标签、还原常见实体后再给模型 —— 把整段 HTML 塞进上下文
既浪费又容易把标签当内容读。

### 10. 好友申请由 AI 判断

**背景**：QQ 的加好友是**单向流程** —— 只能对方申请、你同意。协议层**没有**「主动加好友」
这个动作（实测 `send_friend_request` / `add_friend` 都返回 `retcode 1404 unknown action`）。
所以「他喜欢谁就去加谁」做不到。

**能做到的是**：把「同意谁」的决定权交给他。

```
有人申请加好友（事件，只推一次）
  → 桥接落盘 + 私聊通知操作者（不自动同意）
  → AI 下次唤醒时 qq_friend_requests 看列表
  → qq_accept_friend 决定同意/拒绝
  → 同意 → 自动加进私聊白名单（带名额上限）
```

**它判断的依据**（预设里写了）：验证消息内容、是不是群里的人、记忆里有没有这个人。
**倾向宁缺勿滥** —— 加进来意味着他能私聊你。

**白名单名额上限**：`socialV2.friend.autoWhitelistMax`，默认 10（操作者手动加的不算）。
满了之后仍可同意好友，但不再自动加白名单。

**旧方案已停用**：`friend-accept.cjs` 原来是「一律同意 + 无条件加白名单」的无差别门童，
现在 `recover.ps1` 不再拉起它（否则它会和桥接抢同一批事件、抢先自动同意）。

**他还能主动做的**：在群里 @ 某人说一句「加我好友」—— 这是社交动作，不需要新接口。

### 11. 运维自愈

```
计划任务（每 2 分钟 + 睡眠恢复）→ watchdog.ps1（单实例，持电源请求）
    → recover.ps1
         · 桥接掉了 → 拉起
         · DSH 端口变了（每次启动都变）→ 改配置 + 重启桥接
         · Tulpa 掉了 → 重启
         · SnowLuma 掉了 → 只诊断不重启（见坑表第 1 条）
```

## 五、技术实现要点

### 会话状态是显式字段白名单

`saveSocialV2State` 只保存白名单里的字段。**加新字段必须同时改加载和保存两处**，否则会静默丢弃（踩过：`handoffText` 写完就丢，轮换后摘要丢失，无任何报错）。

### 配置必须走运行时接口

桥接把配置读进内存，自愈时用**内存副本覆盖文件**。直接改 `config.json` 再重启 → 改动被覆盖。

### 工具开关分两层

- **注册期**（`TOOL_CONFIG_FLAGS`）：决定工具是否出现在模型的 schema 里。**改这个要重启 DSH**
- **调用期**（桥接里的 `v2ToolEnabled`）：决定请求是否放行

### MCP 工具服务端

`src/mcp-snowluma-safe.js`（1609 行）暴露 `qq_*` 工具给 agent。**工具名对不上桥接的开关键时，工具静默失效**。

### 意图混淆的防护

- `escapeCqText`：防止文本里的 `[CQ:` 被解析
- `sanitizeQuotedText`：引用里常混进 URL 编码的 JSON 和 Markdown
- `redactKnownTokensOnly`：只脱敏已知令牌，不做通用正则（会把正常文本改坏）

### SnowLuma 的注入是一切的前提

失败时**一行错误都不报**。唯一可靠的诊断：

```powershell
Invoke-RestMethod 'http://127.0.0.1:5099/api/processes' -Headers @{Authorization='Bearer '+$token}
# 返回 {"list":[]} = 没提权 / 没扫到 QQ，别查别的了
# 返回带 injected:true,loggedIn:true = 正常
```

## 六、仓库里有什么、没有什么

**这一节说明白一件事：机制全在，数据全不在。**

| | 在仓库里 | 说明 |
|---|---|---|
| **记忆的算法** | ✅ | 半衰期、权重排序、复活判定、共享池，全在 `bridge.js` |
| **记忆的参数** | ✅ | `socialV2.memory` 可配（半衰期/清理阈值/上限/复活阈值） |
| **记忆的数据** | ❌ | 16 条进行中话题、39 条共享记忆 —— 那是真实群聊内容 |
| **心情的算法** | ✅ | 七根情绪、两级衰减、四道闸 |
| **心情的参数** | ✅ | `socialV2.mood` 可配（半衰期/步长/上限） |
| **心情的状态** | ❌ | `global-mood.json` 是它此刻真实的心情 |
| **人格卡的结构** | ✅ | 20 个章节的模板 + 两段自动生成的格式示例 |
| **人格卡的内容** | ❌ | 真实版 433 行，写满了它群里的人和事 |
| **黑话库的机制** | ✅ | 自举 + 管理员确认的代码路径 |
| **黑话库的条目** | ❌ | 480 条，全部来自真实群聊 |
| **收藏表情的标注** | ❌ | AI 自己对每张表情的理解 |

**为什么数据不带：** 那是你的群的聊天内容、群友的昵称、你和它的私聊。带上就是泄露。

**所以别人装完拿到的是：一条刚出生、会说话、有记忆和情绪机制、但还没有内容的鱼。**

## 九、踩过的坑（全部写进代码注释）

| # | 现象 | 根因 |
|---|---|---|
| 1 | SnowLuma 起来但 3000 永远不通，日志只有一行 "hook auto-load enabled" | 注入器必须提权到**能扫到 QQ 进程**的令牌。计划任务的不行，只有 UAC(consent.exe) 现场创建的才行 |
| 2 | 强杀 SnowLuma 后重启，永远 hook 不上 | QQ 里留着指向死进程的 hook，只能连 QQ 一起重启 |
| 3 | 改 `config.json` 重启就回退 | 桥接用内存副本覆盖文件，必须走 `/api/socialV2/config` |
| 4 | 新状态字段写进去就丢 | 显式字段白名单，要同时加入加载和保存两处 |
| 5 | 欠费时往群里发了 64 条报错 | 原版把 agent 错误当正常回复发出去。现只回操作者私聊 |
| 6 | ffmpeg 抽帧 0 张、音频 0 字节 | DSH 文件沙箱只允许子进程写 workspace 内路径，`%TEMP%` 被拒 |
| 7 | yt-dlp「下载成功」但抽帧 0 张 | 没指定 `--ffmpeg-location` 时它会分开下音视频；而且带版本号的 exe 要给**完整文件路径**，给目录不行 |
| 8 | whisper 退出码 0xC0000409 | 非 ASCII 绝对路径。exe 用绝对路径、`-m`/`-f` 用相对名、cwd 设到 Release 目录 |
| 9 | 95% 的群消息叫不醒它，且不报错 | AI 把 `probability` 写回 0.05。修法是加 `wake.minProbability` 下限钳制 |
| 10 | 安装器在临时目录试跑，覆盖了真实机的计划任务 | 测试必须加 `-SkipSystem` |

## 十、设计原则

**这条最重要：**

> **所有「看起来多余」的检查，都对应一次真实事故。**

| 检查 | 对应的事故 |
|---|---|
| `wake.minProbability` 下限 | 概率被写成 0.05 |
| `shouldNotifyErrorsToQQ` | 欠费时刷 64 条报错到群里 |
| `_video_tmp` 放 workspace 内 | ffmpeg 写 %TEMP% 被拒 |
| `--ffmpeg-location` 给完整路径 | 音视频分开下，静默失败 |
| 字段白名单同时改加载+保存 | `handoffText` 静默丢弃 |
| SnowLuma 只诊断不重启 | 半死实例比不启动更糟 |
| 转达留 `relayNote` | 目标会话不知道那句话为什么出现 |
| `escapeCqText` / `sanitizeQuotedText` | 引用里混进 URL 编码 JSON 和 Markdown |

**其他原则：**

- **不让它执行本地命令**——注册期就把 `pwsh`/`read`/`write`/`subagent` 从工具清单隐藏，不只是执行期拒绝（否则模型会看见、然后反复去调）
- **不把模型输出的错误发给别人**——只回操作者
- **不替角色演情绪**——心情是状态不是剧本，注入永远带松绑声明
- **记忆写得自洽，而不是带前情**——宁可要求转达内容写成「谁、什么事、怎么办」，也不把操作者的私聊泄露给第三方
- **写「她是谁」，不要写「她该怎么说」**——行为规则放 preset（系统提示），性格放人格卡。写「一条最多 15 字」她就会数字说话

## 十一、局限与已知问题

**诚实的部分：**

| 局限 | 说明 |
|---|---|
| **人格卡抄不了** | 模板是骨架。真实的人格卡是从群聊里长出来的，直接抄别人的没用 |
| **记忆重要性靠自评** | 默认 3，AI 自己标 1~5，没有校验。标错就影响遗忘曲线 |
| **只有单群** | 多群需要隔离记忆和注意力名单，还没做 |
| **语音只有输入** | 没有朗读输出，需要先建音色库 |
| **群文件只能看文件名** | 有人发文档它读不了内容 |
| **协议端有封号风险** | 建议一律用小号 |
| **成本不可忽略** | 每条被唤醒的消息都真调一次模型，活跃群一天几块钱 |
| **安装器没在干净机器上验证过** | 我这台已经装好了所有依赖，测不出新手第一次装会遇到什么 |
